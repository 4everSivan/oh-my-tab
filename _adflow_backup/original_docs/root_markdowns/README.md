# oh-my-tab

一个面向公众发布的 Google Chrome 扩展，提供可自定义的新标签页与浏览器启动页，将个人导航、效率工具和视觉氛围整合为一个个人浏览器工作台。

> 当前处于需求规划阶段。本文描述产品目标与设计方向，相关功能尚未实现，仓库暂未提供可加载的扩展或构建脚本。

## 项目目标

- **统一入口**：打开新标签页或启动浏览器时，使用同一套页面与配置。
- **个人导航**：通过搜索、常用网站和分组快捷方式，快速访问需要的内容。
- **效率工作台**：通过待办、便签、日历等组件，组织日常工作与生活。
- **视觉氛围**：通过壁纸、时钟、主题与外观设置，创建符合个人偏好的页面。
- **自由定制**：支持组件自由布局，以及自定义 CSS、外部数据源和扩展组件。
- **公开发布**：面向其他用户设计，考虑安装引导、权限说明、兼容性与版本升级，目标发布渠道为 Chrome Web Store。

## 功能目标

### 导航与搜索

- 提供网页搜索入口，遵循用户现有的浏览器搜索设置。
- 管理常用网站与快捷方式，支持添加、编辑、删除、分组和排序。
- 与效率组件、外观设置组合使用，让用户自行决定页面内容。

### 效率组件

- 规划内置待办、便签、日历等组件。
- 支持按需添加、移除与配置组件。
- 各组件独立展示状态，外部数据源异常时，其他组件仍可使用。

日历组件的首版范围与外部日历服务的接入方式，将在具体设计时确定。

### 外观与自由布局

- 设置壁纸、主题、时钟与页面外观。
- 拖动、缩放和排列组件，并调整导航分组的位置。
- 保存个人布局，兼顾不同窗口尺寸下的展示效果。
- 通过组件开关与布局调整，支持极简页面和内容丰富的工作台。

### 深度扩展

- **自定义 CSS**：允许用户进一步调整页面样式。
- **外部数据源**：允许组件接入用户配置的外部接口，具体服务与认证方式后续确定。
- **扩展组件**：规划统一的组件接口，让开发者增加新的组件能力。

面向 Chrome Web Store 的版本，建议将组件逻辑随扩展打包发布，外部接口用于提供数据。组件扩展的目标是增加工作台能力，具体接口与分发方式仍需设计。

## 新标签页与启动页

计划使用 Manifest V3，通过 `chrome_url_overrides.newtab` 替换 Chrome 新标签页。

启动页接入建议采用用户设置的方式：在 Chrome 的「设置 → 启动时」选择「打开新标签页」，从而在启动时进入同一个工作台，并共用布局与数据。

- 选择「继续浏览上次打开的网页」或「打开特定网页或一组网页」时，启动行为遵循该设置。
- 无痕窗口的新标签页不在替换范围内，这是 Chrome 的平台限制。

该接入方案基于 Chrome 官方文档，实际加载与启动行为仍需在插件实现后验证。

## 数据保存与同步

采用 **本地保存 + 可选 Chrome 同步**，基本功能无需独立的项目账号或自建账号服务。

| 数据类型 | 规划保存方式 | 同步方向 |
| --- | --- | --- |
| 布局、主题选项、组件开关等轻量配置 | 本地保存 | 用户启用后，通过 Chrome 同步 |
| 导航链接、组件配置、自定义 CSS | 本地保存 | 具体范围根据容量与内容敏感性确定 |
| 待办、便签等个人内容 | 本地保存 | 是否同步需进一步确定，不默认上传 |
| 壁纸文件、较大的资源与缓存 | 本地保存 | 不通过 Chrome 同步传输 |
| 外部服务的访问凭据 | 单独设计保存方式 | 不纳入普通配置同步 |

Chrome 同步依赖用户的 Chrome 账号与同步设置。`storage.sync` 的总容量约为 100 KB，单项约为 8 KB，因此同步设计以轻量配置为主，避免承诺所有数据完整同步。

建议同时提供配置导入、导出与恢复默认设置，方便备份和迁移。同步冲突、容量超限与配置版本迁移的处理方式，需要在实现前明确。

## 建议的实现原则

- **默认可用**：提供容易上手的默认布局，高级设置集中在独立入口。
- **本地优先**：页面核心内容与本地组件离线可用，外部请求不阻塞整个页面。
- **快速打开**：优先显示页面与本地内容，再加载外部数据。
- **按需授权**：启用相关功能时说明并申请必要权限，明确外部数据源的请求范围。
- **可恢复**：布局与 CSS 调整出现问题时，提供恢复入口。
- **适配公开发布**：组件代码、数据处理与权限设计遵循 Manifest V3 和 Chrome Web Store 的要求。
