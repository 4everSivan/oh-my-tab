## 3. 规范

1. 总体设计固定为 00-系统总体设计.md；模块采用 01~99-[模块中文名].md，与 Topic 一一对应。
2. 头部包含 created、last-change、status，正文标注 `<!-- @topic: TopicName -->`。
3. 卡片与索引的 design_doc / doc 只指向含匹配 Topic 的真实设计文档，严禁 README。
4. 文档区分已确认需求、建议方案、未决事项与实现证据。
5. 设计不设独立版本号；可选 version 只绑定实际产品发版。draft 转 baseline 须有相应定稿依据。
6. 机器索引的 `confirmed_on` / `confirmed_scope` 仅标注模块中已确认的范围；不将局部确认扩展为整个模块技术方案或功能验收。

## 4. 设计大纲与演进

统一采用四章：1. 简介、2. 索引、3. 规范、4. 设计内容。第四章整合八个方面：背景与定位；目标与非目标；功能和非功能需求；行为与交互；分层架构与 Topic；详细规则、数据模型、接口契约和变更矩阵；存储、权限、扩展与降级；验证标准与参考资料。

变更矩阵固定采用“编号、类型、简介、规则演进”四列。初始化不虚构已完成卡片；后续变更先回写对应设计，再登记 C/T 卡。
