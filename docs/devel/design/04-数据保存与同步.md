## 1. 简介

用户明确选择本地保存加可选 Chrome 同步，不建立独立云账号服务。本模块定义统一数据边界，避免各组件自行决定同步范围。

2026-10-08 已确认首页设置自动保存、独立恢复默认以及内容保留规则，来源见 [总体设计 4.4](00-系统总体设计.md#44-功能行为与交互)。这些是交互契约，不能据此冻结正式存储 API 或同步实现。

需求来源为本次讨论及初始化前的根 README，源文件 SHA-256 为 `5c7ea875cec1db4dbf63743dcbab21a51e8c185436974450bf9567f970e0233a`。原件已备份，根文件保留。本文件是需求基线和方案草案，不是实现或验收证据。

## 4. 设计内容

### 4.1 背景与定位

本地持久化、可选 Chrome 同步、容量边界与配置升级。本次以现有需求文档建立清楚的领域边界，不从通用治理模板推断业务源码或运行环境。

### 4.2 目标与非目标

本地保存工作台状态，并在用户启用时同步适合配额的轻量配置；设计导入导出与恢复方案，以及版本迁移和冲突处理。

不承诺完整同步全部用户数据、大壁纸资源或凭据；不创建独立账号或后端同步服务。本次没有实际同步环境与浏览器数据。

### 4.3 需求清单

| 编号 | 能力 | 需求或规划规则 |
| --- | --- | --- |
| DAT-01 | 本地保存 | 页面布局、外观、导航和个人内容均以本地可用为基础。 |
| DAT-02 | 可选同步 | 用户启用后，通过 Chrome 同步布局、主题选项、组件开关等轻量配置。 |
| DAT-03 | 容量限制 | storage.sync 总配额约 100 KB、单项约 8 KB，设计需处理超限与写入失败。 |
| DAT-04 | 范围分离 | 大资源不经 Chrome 同步；凭据不进入普通配置同步；个人内容是否同步仍需决定。 |
| DAT-05 | 首页设置保存 | 时间、搜索材质、引擎、网站及顺序、背景、组件展示和个人内容本地保留；恢复一组不清空其他数据。 |

非功能方向沿用 README：快速打开、本地优先、权限范围清楚、独立组件失败可降级。量化性能和资源预算仍需首版方案确定，不填入未经验证的指标。

### 4.4 功能行为与交互

建议加载时先读本地数据；保存失败明确反馈，不能报告成功。用户启用同步前展示其范围，离线情况下仍保留本地可用状态。关闭同步的本地数据处理、是否清理远端配置和冲突选择流程需在实现前确定。

已确认首页设置即时预览、自动本地保存，关闭设置面板不回滚已经生效的值。时间与搜索外观可分别恢复默认，默认值唯一来源为 [布局设计 4.6](02-工作台布局与外观.md#46-详细规则与逻辑契约)。网站编辑和拖动结果保存，组件移除保留业务内容，背景图片不上传项目服务端。时间收起为当前页面临时状态，刷新回到展开；搜索查询不作为配置保存。

**存储技术方案决策（2026-10-08）**

2026-10-08 用户决策持久化技术组合：
1. **轻量配置与状态**：采用原生 Chrome Storage API（`chrome.storage.local` 作为本地核心存储，轻量配置按需经 `chrome.storage.sync` 同步）；
2. **大资源与本地壁纸**：采用浏览器原生 IndexedDB 进行二进制/Blob 隔离存储，彻底隔离 Chrome sync 配额风险，避免引入重型外部三方库；
3. **分层仓储适配**：宿主服务提供统一 StorageAdapter 屏蔽底层 Chrome API 与 IndexedDB 差异，并统筹配额跟踪。

### 4.5 建议架构与 Topic

主题锚点为 `DataPersistenceSync`。

建议提供本地仓储、资源存储、同步适配、导入导出与迁移层。具体本地存储组合（Chrome storage、IndexedDB 等）尚未决定。浏览器 API 和配额错误由适配层处理，业务组件使用领域对象，不直接写同步存储。

### 4.6 详细规则与逻辑契约

建议将数据分为轻量配置、个人内容、大资源和凭据。组件实例内容按 `widgets/<instanceId>/content` 命名空间隔离存储，是否进入同步与导出由组件契约的 `syncPolicy` 逐组件声明（见 [组件契约设计 4.6](06-组件契约与注册.md#46-详细规则与逻辑契约)）；配置中出现未知组件类型时，实例与内容原样保留并照常同步。布局/主题/开关属于同步候选；导航、组件配置与 CSS 需评估大小和敏感性；待办便签不默认上传。建议配置携带 schemaVersion 以支持迁移，但键设计、切片策略和数据格式尚未冻结。

**首页状态与恢复边界（已确认）**

| 状态组 | 本地保存 | 恢复或隐藏行为 |
| --- | --- | --- |
| 时间外观 | 字体、字号、字重、位置、阴影、日期/秒数选项 | “恢复时间默认”仅恢复这一组 |
| 搜索外观 | 水平位置、间距、宽度、背景透明度、背景模糊 | “恢复搜索默认”仅恢复这一组，保留引擎 |
| 搜索引擎 | 当前引擎 | 不随外观组恢复而变化 |
| 网站 | 标识、名称、地址及顺序 | 编辑保留标识，排序保留内容，移除可一次撤销 |
| 背景/主题 | 类型、颜色或本地图片引用、裁切位置、遮罩、模糊及主题 | 时间/搜索恢复不改背景与主题 |
| 组件展示 | 已添加类型、顺序与尺寸 | 移除只改展示列表，再添加取已有内容 |
| 个人内容 | 待办、便签等业务数据 | 时间收起、卡片移除或外观组恢复均不清空 |
| 临时交互 | 时间收起、设置面板开关、菜单、搜索查询 | 不保存；重新进入页面按默认交互状态展示 |

**原型兼容规则与正式存储边界**

HTML 原型采用 `oh-my-tab-homepage-study-v2` 保存配置，旧 v1 仅作迁移输入，图片沿用独立的 `oh-my-tab-homepage-study-v1-background` 键。加载旧配置时补齐缺失的时间/搜索字段，保留背景、网站、顺序、待办与便签；显式空网站/空组件列表继续为空。旧 v1 自动放置的组件转为按需添加，原内容保留。

配置进入样式前校验枚举与布尔值，数值限于布局文档范围；无效单字段采用默认值，不将任意字符串注入 CSS。以上键名、localStorage 和图片 data URL 仅描述原型；正式扩展的资源引用、数据 schema、Chrome storage/IndexedDB 组合与原子保存方式需另行设计。导入坏配置、存储写入失败及图片容量边界需单独验证，不能由成功刷新测试推断为通过。

### 4.7 扩展、异常与实施前决策

同步依赖 Chrome 账号与浏览器同步设置。建议处理未登录或未开启同步、断网、配额超限、迁移失败和多设备冲突；保留本地可用性，不静默覆盖用户内容。导出时凭据是否排除及资源如何打包，须单独确定。

需确定准确同步范围、Chrome 同步启停语义、冲突合并策略、写入节流、存储 API、配额预检、导入校验、凭据保存与迁移失败恢复，以及同机多窗口/多标签同时打开工作台时的实时一致性（基于存储变更事件的响应式更新）。尚未决定任何冲突算法。
