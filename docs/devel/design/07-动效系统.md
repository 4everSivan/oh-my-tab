## 1. 简介

2026-10-09 用户提出为本工作台增加交互动效，并指定参考 [transitions.dev](https://github.com/Jakubantalik/transitions.dev)（44 个纯 CSS 可移植动效片段集合，语义化 CSS 自定义属性 + `t-*` 命名空间 + 每个片段自带 `prefers-reduced-motion` 守卫；片段允许个人与商业项目自由使用修改，仅禁止将库本身作为竞品再分发）。

本文件定义 oh-my-tab 的动效令牌体系、片段命名空间、React 集成模式与统一降级守卫，作为动效相关任务的单一设计来源。现有代码中 `animate-fade-in` 类从未在任何样式表定义（Tailwind 默认不含），属于空操作，本设计一并修复。

## 3. 规范

1. **纯 CSS 优先**：动效一律以 CSS `transition` / `animation` 实现，不引入 JS 动效运行时或物理引擎库（依赖克制底线）。
2. **令牌单一来源**：全部时长/缓动/距离/缩放/模糊令牌定义于 `src/styles/motion.css` 的 `:root`；组件代码不得散落硬编码动效参数。
3. **统一降级守卫**：`motion.css` 内置全局 `@media (prefers-reduced-motion: reduce)` 守卫，将所有 `t-*` 动效时长/延迟归零、位移与模糊取消；组件无需逐处处理。
4. **命名空间隔离**：动效片段类名统一 `t-*` 前缀，避免与 Tailwind 工具类冲突；`animate-fade-in` 作为历史既有类名保留并给出真实定义。
5. **可交互性底线**：动画过程中不得阻塞交互（关闭状态 `pointer-events: none`）、不得产生布局抖动（只动 `transform` / `opacity` / `filter`）。
6. 后续动效相关变更先回写本文件，再登记 C/T 卡。

## 4. 设计内容

### 4.1 背景与定位

全站动效的令牌层与片段层。参考 transitions.dev 的方法论（motion tokens 语义梯度 + 可移植片段 + 系统级降级守卫），结合本项目 React + Tailwind 技术栈以纯 CSS 落地；不复制其整库，只移植首版交互面所需的片段并按本项目令牌前缀收敛。

### 4.2 目标与非目标

**目标**：建立统一动效令牌梯度；交付首版 7 类片段并接入对应交互面；修复 `animate-fade-in` 空操作；系统级 reduced-motion 降级。

**非目标**：不引入 JS 动效库（framer-motion/GSAP 等）；不实现 3D tilt、shimmer、confetti 等未列入片段；首版不做用户级"动效开关"偏好（仅系统级 `prefers-reduced-motion`）；不做待办列表项删除的退出动画（仅入场）。

### 4.4 功能行为与交互

| 交互面 | 片段 | 触发 | 开/关时长 | 关键效果 |
| --- | --- | --- | --- | --- |
| 时间数字 | `t-digit` | 数字值变化（key 变更重挂载） | 450ms 单次 | 位移 8px + 模糊 2px + 弹性缓动，tabular-nums 等宽对齐 |
| 待办勾选 | `t-check` | `aria-checked` 切换 | 填充 150ms / 描画 350ms | 背景填充→path stroke-dashoffset 描画，取消 150ms 回退 |
| 添加组件模态 | `t-modal` | `data-open` 属性 | 开 250ms / 关 150ms | scale 0.96→1 + 淡入淡出，smooth-out |
| 外观抽屉 | `t-panel-slide` | `data-open` 属性 | 开 400ms / 关 350ms | translateX(100%)→0 + 模糊 2px 交叉淡化 |
| 栅格卡片 | `t-card-enter` | 挂载 | 400ms + 交错延迟 | 上升 12px + 模糊 2px + 淡入，`--card-index` 控制步进 |
| 工作台折叠 | `workspace-container` | 点击时间收起/展开 | 350ms | 时钟与搜索框零位移；max-height + scale 0.98 + translateY(-12px) 平滑折叠 |
| 快捷方式图标 | `t-stagger-item` | 挂载 / 交互 | 400ms 级联 | 35ms 步进升起，悬停微浮，active:scale-95 弹性按压 |
| 源点感知菜单 | `origin-menu` | 右键 / 引擎切换 | 200ms | 源点缩放 scale 0.94→1.0 + blur 2px 柔和展开 |
| 专注时间切换 | `t-tabs-sliding` | 点击时间预设 | 250ms | 高亮药丸背景平滑位移与变形 |
| 撤销通知条 | `t-toast` | 移除常用网站 | 300ms | 底部边缘 translateY(16px) + scale 0.97 弹入升起 |
| 通用区块 | `animate-fade-in` | 挂载 | 250ms | 纯淡入（header、收起/展开区块等既有引用点） |

React 集成约定：进入动画靠挂载时 CSS `animation` 自然播放；退出动画由 `useDelayedUnmount(isOpen, closeDuration)` Hook 支撑——关闭时保持挂载并翻转 `data-open`，超时后再卸载 DOM。进入态翻转前先强制同步回流（读取 `offsetHeight`）确保关闭态样式已参与布局，不依赖 `requestAnimationFrame`（被遮挡/不绘制的标签页会节流 rAF 导致进入动画失效），与参考库文档的 "force a reflow, then re-add the class" 重放机制一致。数字位使用含字符的 key（`${position}-${char}`），数值不变的位保持 DOM 节点不重放动画。

### 4.5 建议架构与 Topic

主题锚点为 `MotionSystem`。

三层结构：`src/styles/motion.css`（令牌层 + 片段层 + 守卫，经 `index.css` 引入）→ 组件 `className` / `data-open` / `aria-checked` 接线层 → `src/hooks/useDelayedUnmount.ts` 与 `src/utils/motion.ts`（纯函数：交错延迟计算）支撑层。布局层（GridContainer）与组件（Clock、Todo）只消费片段类名，不感知彼此实现。

### 4.6 详细规则与逻辑契约

**令牌梯度**（摘录，完整以 `motion.css` 为单一来源）：

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--motion-duration-micro` | 80ms | 微交互延迟 |
| `--motion-duration-quick` | 150ms | 模态关闭、勾选填充 |
| `--motion-duration-fast` | 250ms | 模态开启、通用淡入 |
| `--motion-duration-medium` | 350ms | 抽屉关闭、列表入场 |
| `--motion-duration-slow` | 400ms | 抽屉开启、卡片入场 |
| `--motion-ease-smooth-out` | cubic-bezier(0.22, 1, 0.36, 1) | 开合、位移类统一缓动 |
| `--motion-ease-spring` | cubic-bezier(0.34, 1.36, 0.64, 1) | 弹入（数字、勾选描画） |
| `--digit-*` / `--check-*` / `--modal-*` / `--panel-*` | 见片段 | 片段私有参数组 |

**交错延迟纯函数**：`computeCardStagger(index, stepMs = 40, capMs = 360) = min(index × stepMs, capMs)`，超出封顶后同批余量卡片同时入场，防止长列表尾部等待。

**守卫规则**：全局守卫将 `t-*` 选择器的 `animation-duration`/`transition-duration`/`animation-delay`/`transition-delay` 置为 `0.01ms`，`animation-iteration-count` 置 1；`animate-fade-in` 同样收敛。守卫不改变 `display`/`visibility` 语义，关闭态遮罩仍由 `data-open` 控制。

### 4.7 扩展、异常与实施前决策

纯 CSS 方案在扩展环境离线可用，无网络与权限依赖。退出动画依赖 Hook 定时器，组件卸载时清理定时器防泄漏。后续若新增片段（如搜索引擎切换 icon-swap、表单校验 error-shake），按本文件规范扩展令牌与 `t-*` 片段并回写 4.4 映射表；用户级动效偏好开关若立项，需定义其与系统 `prefers-reduced-motion` 的合并优先级。
