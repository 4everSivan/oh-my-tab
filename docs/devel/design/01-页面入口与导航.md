## 1. 简介

用户确认两个入口均需支持，个人导航是工作台的核心能力之一。本模块负责进入工作台与访问网站，不承担布局持久化或外部效率服务集成。

2026-10-08 已确认当前网页搜索与网站管理交互，来源见 [总体设计 4.4](00-系统总体设计.md#44-功能行为与交互)。入口接入、分组及正式 Chrome 图标能力仍需具体设计。

## 4. 设计内容

### 4.1 背景与定位

新标签页和启动入口、网页搜索、常用链接与导航分组。本次以现有需求文档建立清楚的领域边界，不从通用治理模板推断业务源码或运行环境。

### 4.2 目标与非目标

提供网页搜索、常用网站管理、快捷方式分组与排序，并与其他工作台组件共存。

页面独立选择搜索引擎，不改变浏览器全局搜索提供方，不自动修改其他启动模式。是否读取 Chrome 原生书签或历史记录尚未讨论，不能从“常用网站”推断该权限需求。

### 4.3 需求清单

| 编号 | 能力 | 需求或规划规则 |
| --- | --- | --- |
| NAV-01 | 页面入口 | 新标签页替换；启动时进入同页采用 Chrome 的启动设置引导。 |
| NAV-02 | 搜索 | 页面搜索默认 Google，用户可切换搜索引擎；不更改浏览器全局搜索设置。 |
| NAV-03 | 链接管理 | 常用网站支持添加、编辑、删除、分组与排序。 |
| NAV-04 | 共享状态 | 两个入口读取同一持久化配置，不生成重复导航数据。 |
| NAV-05 | 网站配置与图标 | 默认及自建网站均可编辑名称/地址；自动获取图标，失败时用名称首字符，统一连续圆角。 |
| NAV-06 | 桌面式操作 | 右键菜单打开编辑窗口；长按后拖动排序，短按保持访问行为。 |

非功能方向沿用 README：快速打开、本地优先、权限范围清楚、独立组件失败可降级。量化性能和资源预算仍需首版方案确定，不填入未经验证的指标。

### 4.4 功能行为与交互

新增链接时填写名称和地址，修改或删除作用于选中的链接，排序和分组修改交由持久化模块保存。网页搜索提交到页面选定的引擎；设置中说明新标签页与浏览器启动设置的关系。

**网页搜索（已确认）**

首页搜索默认 Bing（或 Google），当前仅支持并保留四款精选搜索引擎：必应 (Bing)、谷歌 (Google)、GitHub 与 Bilibili，选择结果本地持久化；不修改 Chrome 全局搜索提供方。输入搜索网页，提交后在新标签页打开选定引擎并保留首页。空白查询不发起请求，查询文本经引擎对应参数正确编码（如 GitHub 的 `q`，Bilibili 的 `keyword`）。它与“筛选常用网站”分开，不将用户的网页查询当成网站过滤条件。

搜索框左侧切换按钮全量采用各家品牌矢量 Logo 图标替代文字，并严格保证图标尺寸一致（18x18px，保证视觉规范一致）。点击图标展开的搜索引擎选择下拉菜单样式与搜索框完全同质化（共享相同的背景透明度、高斯模糊 backdropFilter 与圆角），并在弹出时获得顶层 z-index 保护，且具备点击空白外部快速关闭能力。搜索框外观与位置规则见 [布局设计 4.6](02-工作台布局与外观.md#46-详细规则与逻辑契约)。

**网站配置与图标（已确认）**

默认网站与自行添加的网站使用相同编辑流程：配置名称和地址，支持添加、移除及排序。只接受 HTTP(S) 网页地址，缺省协议补 HTTPS，无效地址在编辑窗口反馈。图标自动获取；样稿依次尝试站点根目录的 `favicon.ico`、`apple-touch-icon.png`，5 秒内未取得则显示名称首字符。英文首字符大写，中文显示第一个字，emoji 尽量保留完整字符。名称在图标下方显示，所有网站和添加入口使用同一连续圆角轮廓。默认网站名单是当前样稿示例，正式内置名单另行确定。正式扩展可评估 Chrome `_favicon` 能力，权限和实机验证另行处理。

网站日常不显示管理按钮。右键图标弹出桌面式菜单，提供编辑、打开、移除及添加；编辑进入名称与地址窗口。长按图标约 450 ms 后进入拖动，再拖到目标网站位置并松开，保存新顺序。快速点击仍打开网站，拖动结束不触发打开。键盘可用 Shift+F10 打开菜单、Escape 关闭，以及 Alt+左右方向键排序。菜单贴近点击位置并避让窗口边缘；移除后可撤销一次。

编辑窗口打开时填入现有值并聚焦名称；取消保留旧值，保存后更新该网站，不能新增重复记录来替代编辑。菜单支持上下方向键和 Home/End 选择项，关闭或取消后恢复网站焦点。新增网站入口常驻，网站编辑入口集中在右键菜单。

### 4.5 建议架构与 Topic

主题锚点为 `EntryNavigation`。

建议分为入口适配、导航领域数据与搜索适配三部分。入口只负责加载工作台；导航操作通过持久化模块保存；布局模块决定分组的展示位置。入口与导航不直接处理同步协议或外部数据源。

### 4.6 详细规则与逻辑契约

Shortcut 至少包含稳定标识、显示名称、HTTP(S) 地址和顺序；分组对象及交互仍待设计。修改名称/地址保留标识和相对顺序，修改地址后重新取得图标；排序仅改变网站顺序。图标结果不承担网站身份，缺图不影响链接打开。

| 原型约束 | 当前值或规则 | 正式实现边界 |
| --- | --- | --- |
| 名称 | 去除首尾空白后 1–30 个字符 | 保留非空校验，正式长度限额需验证 |
| 地址 | 有效 HTTP(S)，不允许 URL 中嵌入用户名/密码；上限 2048 字符 | 不支持可执行协议或本地文件链接 |
| 图标来源 | 仅配置网站的 origin，顺序 favicon → touch icon；5 秒回退 | 正式 Chrome 图标 API、缓存和权限待定 |
| 长按排序 | 阈值 450 ms，拖动成功后保存，禁止带出点击导航 | 实际鼠标/触控板体验待验证 |
| 网页搜索 | 选定引擎（必应/谷歌/GitHub/Bilibili）、查询参数与 URL 编码；空白不提交 | 实际 Chrome 新标签页打开待验证 |

正式存储键、标识生成及浏览器 API 契约尚未冻结；页面初始焦点与 Chrome 地址栏行为需要实机验证。

### 4.7 扩展、异常与实施前决策

建议对无效输入提供明确反馈，保存失败时不显示成功。核心链接数据从本地加载，外部图标或网络资源异常不阻塞导航。浏览器选择恢复上次页面或固定启动网页时，遵循该设置；无痕窗口不覆盖新标签页。

样稿采用新标签页打开网页、网站自身图标及 HTTP(S) 限制，并提供键盘操作。正式扩展仍需确定分组交互、Chrome 图标 API 权限与实机兼容性。原生书签导入属于另行讨论的能力。

### 4.8 后续验证与参考资料

2026-10-07 的 HTML 原型已验证网站编辑、添加、首字符回退、移除撤销、引擎切换与刷新保存，以及右键菜单和编辑窗口，记录于 `local/homepage-minimal-browser-check.json`。排序规则和长按阈值有 Node 回归；键盘排序不能代替指针长按手感验证。2026-10-08 用户确认上述设计，不代表实际 Chrome 导航结果已验收。

正式实现需核验：默认 Google、引擎选择刷新保留；合法 URL 编辑保持同一记录，无效输入不保存；缺图仍能辨认并打开网站；右键菜单避让边缘且可键盘操作；短按打开、长按拖动不误打开、顺序刷新保留；两个入口一致性及三种启动模式。分组与实际搜索新标签页仍待实现和验证。
