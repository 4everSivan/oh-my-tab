## 4. 设计内容

### 4.1 背景与定位

组件注册契约、外部接口接入、权限与请求降级。本次以现有需求文档建立清楚的领域边界，不从通用治理模板推断业务源码或运行环境。

### 4.2 目标与非目标

规划统一组件接口和可配置外部数据源，使新增能力与内置组件一致集成到工作台中。

本次不建立组件市场、远程脚本安装器或任意代码解释器；没有确定通用任意 API 编辑器或外部服务名单。扩展分发方式仍需设计，当前默认建议为随扩展版本打包。

### 4.3 需求清单

| 编号 | 能力 | 需求或规划规则 |
| --- | --- | --- |
| EXT-01 | 扩展组件 | 提供明确组件接口，让开发者增加工作台组件。 |
| EXT-02 | 外部数据 | 组件能够连接用户配置的外部接口，认证方式后续确定。 |
| EXT-03 | 公开版本 | 建议组件逻辑随扩展打包，外部接口返回数据，按功能说明和申请权限。 |
| EXT-04 | 降级隔离 | 加载或权限失败只影响相关组件，不阻塞页面其他内容。 |
| EXT-05 | 真实 RSS/Atom 订阅 | 原生解析 RSS 2.0、Atom 与 JSON Feed 协议，清洗 HTML 标签与格式化相对时间（纯日期 `YYYY-MM-DD` 按本地日历日解析，不随时区偏移，C033）；预置高质量真实公开源，支持用户添加/管理订阅源。 |
| EXT-06 | 极客自定义脚本源 | 支持用户配置自定义 JavaScript 转换脚本，将任意 API 或 JSON 数据转换为标准订阅流格式，具备沙箱异常隔离。 |
| EXT-07 | OPML 导入导出 | 支持标准 OPML 文件导入批量订阅与一键导出备份，实现与其他 RSS 阅读器的数据互通。 |
| EXT-08 | 跨域与免打扰通知 | Chrome 扩展端经 Background Service Worker 透明代理跨域抓取（零 CORS 阻断）；未读消息仅通过顶栏呼吸红标呈现，绝不弹窗打扰用户。 |

非功能方向沿用 README：快速打开、本地优先、权限范围清楚、独立组件失败可降级。量化性能和资源预算仍需首版方案确定，不填入未经验证的指标。

### 4.4 功能行为与交互

**真实 RSS / Atom / JSON 订阅源与文章聚合 (T18)**

为了让订阅侧边栏摆脱死板的假数据，成为真正具备情报价值的生产力中心，建立以下数据与呈现规范：
- **原生零依赖 XML/Atom 解析**：使用浏览器原生 `DOMParser` 解析 XML 文本，智能提取 `<item>` / `<entry>` 中的标题、链接、发布时间与摘要（`<content:encoded>` / `<description>` / `<summary>`），正则清洗掉内嵌的图片、HTML 脏标签与冗余脚本，提纯出清晰的 100~140 字摘要；
- **真实开箱预置源**：默认装配 3 个精选高质量公开 RSS 源（如阮一峰的网络日志 Atom、少数派 RSS、V2EX 每日精选），新用户一键打开即可看到真实世界的科技与开发资讯；
- **全生命周期源管理 (Source Manager)**：侧边栏支持“消息流 (Timeline)”与“源管理 (Sources)”双视图平滑无缝切换；用户可启停指定源、删除源、新增源，以及一键重置为精选推荐源；
- **OPML 生态互通**：支持导入 `.opml` / `.xml` 订阅单，自动提取所有 `<outline>` 节点一键批量入库；支持导出标准 OPML 文件下载；
- **极客自定义脚本源 (Script Sources)**：允许用户针对无 RSS 的自建接口或特定 API 编写微型转换脚本（如 `(data) => data.map(...)`），沙箱隔离执行，异常捕获降级；
- **静默免打扰体验**：新文章只计入侧边栏未读状态与顶栏 🔔 红色呼吸角标，严禁触发桌面操作系统弹窗通知；
- **本地增量缓存与手动刷新**：文章列表缓存于本地存储，侧边栏顶部提供 🔄 手动刷新按钮（带优雅加载旋转动效），支持一键全部标为已读。

### 4.5 建议架构与 Topic

主题锚点为 `ExtensionDataSources`。

建议由订阅源管理服务（`FeedService`）、原生协议解析器（`FeedParser`）、脚本执行器（`ScriptExecutor`）、OPML 互通器（`OpmlService`）与 MV3 后台网络代理构成。

### 4.7 扩展、异常与安全边界 (C024 强化)

1. **零第三方公共代理转发 (Zero External Proxy Leaks)**：订阅源拉取直连失败或鉴权受阻时，必须直接向调用方抛出错误，严禁向未经用户显式配置和授权的任何第三方公共只读代理（如 `allorigins.win`）转发用户 URL，防止私有 Token 或内网敏感拓扑泄露；
2. **完整响应体超时守护 (Full-Body Request Timeout)**：后台 Service Worker 的网络请求函数必须使用 `try-finally` 确保计时器贯穿至 `res.text()` 完整响应体读取结束，彻底杜绝“慢速响应体卡死挂起”缺陷；
3. **安全声明式数据提取 (Declarative Data Extraction)**：遵循 Chrome MV3 默认内容安全策略（CSP），严禁使用 `new Function` 或 `eval` 执行字符串代码。自定义数据源采用安全字段路径匹配与纯 JSON/声明式模式映射引擎进行字段提纯；
4. **搜索联想失败语义保全**：非百度引擎（如 Google / Bing）网络或解析失败时，直接返回空联想数组，严禁静默回退百度，确保用户隐私与引擎偏好一致。

### 4.8 订阅刷新并发与状态一致性契约 (C026 强化)

1. **增量源元数据写回与代次控制 (Generation & Incremental Sources Update)**：`refreshAllFeeds` 在网络拉取结束后，必须重新获取最新源列表 `latestSources`，仅增量更新仍存续源的 `lastFetchedAt`、`itemCount` 和 `lastError`；若刷新期间有新刷新触发，已过期的刷新代次不得写回源配置；拉取期间用户删除的源，其抓取的文章必须被彻底丢弃，严禁让已删除的源借由旧快照回写“复活”；
2. **阅读状态最终快照一致性 (Read State Preservation)**：在网络请求完成、合并文章缓存之前，必须重新读取本地文章存储中的最新已读状态，以最新状态为准注入条目，杜绝用户在数秒网络等待期间标记的已读文章被旧快照回滚；
3. **空源配置合法性保全 (Empty Sources Preservation)**：订阅源配置仅在存储键完全不存在（`raw === null`）时才自动装载 4 个精选默认源；若存储中存在合法的空数组（`[]`），必须严格尊重用户的清空操作，严禁判定为“未初始化”而强制重新写入默认源并自动联网；
4. **卡片点击幂等已读 (Idempotent Mark Read)**：用户在侧边栏卡片上点击阅读文章并打开链接时，采用 `markItemRead` 幂等标记已读；已读文章重复点击打开原文不再翻转为未读，且不触发冗余的存储持久化；
5. **条目数量上限一致性与 OPML 规范化**：刷新函数返回的文章条目数组必须与本地存储持久化集合一致截断至 150 条上限；OPML 导入去重遵循 RFC 3986，仅将协议与域名转小写，严格保留路径与参数的原始大小写。
