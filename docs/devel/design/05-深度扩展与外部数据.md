## 1. 简介

用户选择在自由布局之上支持自定义 CSS、外部数据源和扩展组件，并要求面向公众发布。CSS 的具体外观行为由布局模块承担，本模块负责组件与数据接入边界。组件契约、注册表与实例模型的单一来源自 2026-10-08 起收拢至 [06-组件契约与注册.md](06-组件契约与注册.md)；本文保留外部数据源、权限、分发与降级职责。

## 4. 设计内容

### 4.1 背景与定位

组件注册契约、外部接口接入、权限与请求降级。本次以现有需求文档建立清楚的领域边界，不从通用治理模板推断业务源码或运行环境。

### 4.2 目标与非目标

规划统一组件接口和可配置外部数据源，使新增能力与内置组件一致集成到工作台中。

本次不建立组件市场、远程脚本安装器或任意代码解释器；没有确定通用任意 API 编辑器或外部服务名单。扩展分发方式仍需设计，当前默认建议为随扩展版本打包。

### 4.3 需求清单

| 编号 | 能力 | 需求或规划规则 |
| --- | --- | --- |
| EXT-01 | 扩展组件 | 提供明确组件接口，让开发者增加工作台组件。 |
| EXT-02 | 外部数据 | 组件能够连接用户配置的外部接口，认证方式后续确定。 |
| EXT-03 | 公开版本 | 建议组件逻辑随扩展打包，外部接口返回数据，按功能说明和申请权限。 |
| EXT-04 | 降级隔离 | 加载或权限失败只影响相关组件，不阻塞页面其他内容。 |

非功能方向沿用 README：快速打开、本地优先、权限范围清楚、独立组件失败可降级。量化性能和资源预算仍需首版方案确定，不填入未经验证的指标。

### 4.4 功能行为与交互

建议先登记打包组件，再允许用户添加实例并配置数据源。启用联网能力时说明访问范围；权限或认证缺失时显示可操作的状态。数据源返回值经校验后进入组件，取消或切换实例时停止过时请求，具体生命周期在接口设计中明确。

### 4.5 建议架构与 Topic

主题锚点为 `ExtensionDataSources`。

建议由数据源适配、权限管理与请求生命周期组成；组件注册表、实例生命周期与配置描述的契约已收拢至 [06-组件契约与注册.md](06-组件契约与注册.md)，内置和扩展组件共享同一可验证契约。布局与持久化分别由对应模块提供。数据适配仅返回数据，不承担远程执行逻辑。

### 4.6 详细规则与逻辑契约

组件声明字段统一采用组件契约的 WidgetManifest（见 [组件契约设计 4.6](06-组件契约与注册.md#46-详细规则与逻辑契约)）；本文定义其中数据源声明访问目标、认证引用、输入输出和失败状态的规则。具体 TypeScript 接口、注册方式、请求协议、字段映射与兼容机制尚未冻结。凭据通过独立引用关联，不进入可同步普通配置。

### 4.7 扩展、异常与实施前决策

公开版本按 Manifest V3 和商店要求设计。网络错误、拒绝授权、认证失效、超时与响应格式异常在单组件处理；具体超时、缓存和重试预算未决定。扩展组件不得通过约定的数据接口获取无关权限或任意工作台内容。

需确定组件接口与版本兼容、扩展组件分发、允许的外部接口、认证类型、权限申请、响应校验、请求取消、缓存与重试预算。用户的 CSS 入口不等同于 JavaScript 执行入口。
